# 普通项目 Agent

| 元信息 | 内容 |
| --- | --- |
| 维护状态 | 持续维护 |
| 目标读者 | 产品、开发、测试与运维人员 |
| 事实来源 | 普通项目契约、standard 流水线、Pi SDK、供应商启动初始化测试 |

## 概述

新建项目默认普通版，已保存项目必须提供明确模式；历史格式会被拒绝。模式创建后不可切换，与收费无关。专业版继续使用原有阶段、依赖、覆盖和检查机制。普通版直接从需求描述生成课程设计图表，一个项目保存一段持续会话，后续消息可以修改指定图表。

普通版内容区使用 assistant-ui 官网首页演示及其依赖源码，包括 Thread、Composer、消息、引用、附件、模型选择、完整反馈弹窗、耗时、后续建议、用量提示和基础 UI。保留源码的示例、Public Sans 与 JetBrains Mono 字体、布局、主题及动画；文案随平台中英文设置切换，用户消息、附件名和引用资料不翻译。平台侧栏和顶栏继续使用平台组件。Agent 发起的交互式询问由 integration 边界接入原消息正文，不修改导入组件；内容区不添加自制状态栏、继续卡片、产物卡片或设置提示。

source-manifest.json 记录导入组件、工具文件及样式源文件的来源、原始内容、语言适配及 JSX 结构校验值。社区版保留原始 JSX 元素、属性及样式类，通过 integration 边界接入平台身份、持久会话、模型选择、附件和实际用量，并将弹层放入独立主题容器；社区适配与校验值另有记录。模型选择器旁使用项目共享 Switch，选择器弹层仅显示模型列表。LLM 调用 ask_questions 产生问题、选项、推荐及单选或多选信息，前端复用同一询问组件提交结构化答案，也保留文字回答入口。社区版不连接官网演示账号、商业计费或遥测服务；项目权限与调用限流继续由本地 API 校验。

## 当前设计或配置

### 官网演示接入范围

当前使用官网内容区组件，不代表官网运行时的全部功能均已接入。维护时需要分别验证组件、数据和操作是否完整，不能仅以按钮已显示作为完成依据。

| 功能 | 当前状态 |
| --- | --- |
| 消息、推理、工具记录、引用、复制、导出、停止、模型选择、原版反馈弹窗 | 已连接平台现有数据与操作 |
| 编辑消息、重新生成回复 | 原版控件已连接受管任务；从所选用户轮次重新回复，保留附件和引用，并检查最新消息 ID 防止覆盖其他窗口的更新 |
| 版本分支切换 | 本轮未接入可选择的历史版本；后台保留原始 Pi 记录，页面只显示服务端当前对话 |
| 后续建议 | 原版 FollowUps 显示本轮对话实际生成的最多三条建议，随回复保存；不再使用固定平台建议 |
| 反馈原因和补充说明 | 原版表单已显示；平台目前只持久化正面或负面类型，原因和补充文字未入库 |
| 回复统计 | 新回复持久化首内容耗时、总耗时、内容块数和基于供应商输出 Token 的生成速度，使用原版耗时提示；历史缺失字段不补造 |
| 附件 | 接入平台限定的文本、Markdown 和视觉模型图片；未使用官网云文件存储，不支持 PDF、Word 等额外类型 |
| 斜杠命令 | 原版菜单和指令标签已显示；命令说明尚未随平台请求传给后端 |
| 结构化来源、文档检索、天气、图片搜索、交互看板及游戏 | 后端未连接官网工具集；对应来源和生成式界面没有完整数据通路 |
| 会话侧栏、重命名、归档、置顶、记忆管理页、全屏及其快捷键 | 未导入官网外壳，继续使用平台侧栏与顶栏；平台项目记忆不等同于官网浏览器记忆页 |
| 官网账号、每日演示额度及遥测 | 不连接官网服务，使用社区版账号、BYOK 与本地调用限流 |

朗读和语音输入仅在浏览器提供相应能力时显示，语音输入仍需用户授予麦克风权限。模型推理开关仅在能力资料确认支持推理时显示，Token 依赖真实报告用量，单版本时分支导航按源码规则隐藏。这些条件不应与尚未接入的数据通路混淆。

### 会话与工具

后端实际使用 Pi SDK 的 `createAgentSession`、工具循环、SessionManager 和自动压缩。社区版锁定已修复安全公告的 `@earendil-works/pi-coding-agent`、`pi-agent-core`、`pi-ai` 版本 `1.3.0`，要求 Node.js 22.19.0 或更高版本。升级需同时核验 SessionEntry 格式、扩展事件和会话恢复契约；当前服务仍仅加载受管项目工具，不加载主机扩展或个人凭证。

Agent 通过受管供应商的 OpenAI 兼容接口调用原生工具。工具仅支持读取当前项目、追问、保存共享方案、生成或保存图表、按需生成测试及说明书、保存项目约定。API 服务主机的文件、终端、扩展目录、技能和个人凭证不加载到会话中。

每轮先持久化用户消息，再启动工具循环。Pi 原始消息和工具记录保存在项目工作区的服务端字段，客户端不能覆盖。界面使用独立的用户可见对话；MCP 提供已保存的需求、约定、方案、模型与测试预期，不暴露内部工具历史。社区版不提供运营管理端。

### 生成与修改

仅粘贴需求不代表授权生成全部模型。首次未指定产物时，服务保存需求并将 generationScope 标记为等待选择；LLM 根据用户需求解释可选模型，并通过 ask_questions 发起 purpose=generation_scope 的多选询问。系统支持功能结构、用例、业务流程、总体架构、概念 E-R、设计类、时序、数据库表关系八类模型，通常推荐从功能结构、用例和业务流程开始。询问内容由 LLM 决定，组件只显示问题和收集答案；不能用固定文字代替工具询问。生成入口和工具均拒绝尚未确认的范围。用户首条消息已明确要生成的模型时直接采用，不重复确认。

范围确认后，总 Agent 统一识别角色、全部业务、实体和约束；缺少关键业务信息时先追问，充分时保存共享方案。图表任务并发上限为三，仅创建所选类型的任务；业务流程和时序各按每项业务生成。后续扩展范围不会删除已有模型。

后续修改优先读取并保存指定图；需要重生成时必须提供具体图表 ID。写入工具同时校验本轮模型类型范围，其他已保存图保持原值。同类存在多张业务图而用户未指定业务时，Agent 应先询问具体目标。

普通版只校验模型结构并执行确定性 PlantUML 渲染。每类图的生成 Schema、提示词和本地校验共用相应的节点与关系类型，避免混入其他模型的结构。结构错误最多补充修复一次；供应商错误直接保留失败状态。单图失败不删除其他成果，结束时会话给出成功、失败数量及原因。修改单图不触发其他图、测试或文档的过期检查。测试和说明书保留单独按钮，也可通过用户明确的会话请求生成。说明书保存生成时的图表快照。

主动停止、失败或服务重启中断时，运行中的工具同步结束为失败，并在会话中说明原因与已完成、未完成数量。历史终态记录若遗留运行中的工具，在读取时修复显示，不重新启动生成。

### 导航与按需产物

普通版与专业版共同使用 ProjectSidebar 和 ProjectSidebarNavigation，统一项目导航、管理分组、展开动画、状态提示、缩进、图标模式浮层、拖动调宽与 Coding Agent 卡片。普通版只提供不同的菜单数据，不显示链路入口。“UML 模型”一级入口打开会话；图类别作为二级入口，多业务或角色的具体图表放在三级，默认逐级收起。三级名称去掉重复的图类型后缀，保存标题不变。

测试页复用专业版统计卡片、场景筛选和用例表格，普通版仅显示关联业务与模型，不启用专业版依赖或覆盖检查。旧用例没有场景类型、优先级时显示未分类、未标注。

说明书只提供需求规格说明书与软件设计说明书，使用共享 DOCX 排版器保存到项目文档库，并支持内置预览与下载。普通任务不写入专业版运行记录外键；生成失败或取消保留已有文件。需要编辑时，在本地 Word 兼容编辑器中修改下载文件，不依赖文档编辑服务器。

### 模型容量目录

后端从 [Modelpedia 公开接口](https://modelpedia.dev/docs/api)读取模型名称、生命周期、容量和能力，在启动时加载持久缓存，缓存过期后更新，此后每 24 小时同步。供应商和模型分页全部验证通过后才发布快照，下载有超时、大小和总模型数限制，失败保留上次成功的 Modelpedia 快照；旧目录版本不会作为新资料读取。用户请求只读取后台缓存，不直接下载目录，也不向目录发送供应商凭据或项目内容。

先按精确模型 ID 与 Modelpedia 的 created_by 汇集短名称和完整名称下的同一规范模型，再优先读取当前接口、原厂及同一规范模型的已知容量；不删除版本号、不模糊匹配。上下文与最大输出量独立解析，空记录和缺失输出量不会挡住已有上下文容量。同一规范模型缺少当前接口或原厂字段时，采用目录中各渠道已知数值的最小值作为保守参考；不同规范模型不会合并，身份无法确认时相互冲突的字段保留未知。社区版使用自动目录与保守回退预算，不提供官网运营端的人工容量补充及手动同步入口。

推理、视觉和工具调用能力独立于容量匹配，优先使用对应接口记录，再汇总精确 ID 及同一规范模型的明确记录。未填写字段不否定已有确认；全部缺失或明确值相互冲突时保留未知。目录中的 reasoning、context_window 和 max_output_tokens 分别用于推理能力、上下文容量和最大输出量，不能用接口结构化输出模式代替这些字段。

首页保留原版模型选择控件，推理控制按用户要求改为输入框底部、模型选择器旁的项目共享 Switch，不放在模型列表内，也不在模型名称后显示 Yes / No。开关仅在当前模型确认支持推理时出现，只读或运行期间禁止切换；旧偏好的 low 和 medium 标识分别保留为关闭和开启，避免改变已有状态。内容区样式构建扫描共享 Switch，保证其尺寸、状态和动画样式在独立主题内生效。DeepSeek 请求保留原生 thinking.type=enabled/disabled 开关，移除 SDK 内部启用级别生成的 reasoning_effort 参数；其他模型继续使用各自供应商的参数适配。

Pi 默认采用匹配容量；显式设置 UML_STANDARD_CONTEXT_TOKENS 只会降低运行预算。资料未知时临时使用 48,000 Token；首页可以显示真实运行预算，但在用量提示中明确标注“当前预算”，不宣称是资料容量。强 JSON、JSON 与兼容模式继续来自供应商接口探测：结构化生成分别发送严格 Schema、json_object 或普通文本请求，并执行平台结构校验；公开目录不覆盖该探测结果。更新应用于后续会话调用，不改写当前运行保存的用量口径。

### 记忆与压缩

会话记录、当前模型和长期约定分别保存。每轮读取当前已保存状态；需要细节时按 ID 读取相关图，避免反复塞入全部 SVG。长期记忆只存本项目稳定约定，用户可以在会话中要求更正。

Pi 根据上下文预算自动选择压缩边界，保留工具调用与结果的对应关系。摘要经平台调度与调用限流入口生成，保留目标、确认约束、已完成修改、未解决问题和下一步。压缩缩短送给模型的上下文，原始历史仍保留。默认预算取自动匹配的容量；只有资料未知时临时使用 48,000 Token。`UML_STANDARD_CONTEXT_TOKENS` 可设置更小的运行预算。

恢复时重建 Pi 会话树和压缩记录；中断后缺少结果的工具调用标记为中断，避免自动重复修改。每个项目同时执行一轮，执行期间可以停止；异常保留对话与已完成产物。

### 交互与恢复

消息、工具记录和推理折叠使用官网首页原组件；图表、测试和说明书从平台侧栏进入，不往消息区插入独立产物面板。图表详情页显示保存的 SVG，通过净化 SVG 标记过滤脚本和不安全内容，支持缩放、复位和弹窗展开。

编辑和重新生成均使用原版控件，重新生成重用所属用户轮次的文字、附件和引用。服务端在受理任务的工作区并发更新中校验目标与最新消息 ID，移除所选轮次及其后续可见消息，并将 Pi 上下文移到该用户轮次前的私有检查点。检查点同时保留当时的追问状态；已压缩的后续摘要不会混入新回复。缺少当前检查点时拒绝编辑或重新生成，并提示发起新一轮对话。原始会话树保留，当前界面不提供版本切换；已执行的图表、测试、说明书和项目记忆不会因编辑对话自动回滚。

耗时组件优先读取新消息保存的 timing，兼容历史 durationMs。首内容时间从开始等待该条模型回复到首个非空文本、推理或工具参数块；内容块数统计这些实际增量事件，速度使用供应商报告的输出 Token 除以首块至结束的时长。未报告用量、未出现增量块或历史缺失字段时不推测速度和首内容耗时。

后续建议沿用官网的一行一条协议与原版 FollowUps，通过平台受管模型按最近六条消息生成，最多三条，并随最后一条成功回复保存。提示最多 24,000 字符，输出最多 1,024 Token，等待上限 15 秒，语言跟随提交时的界面语言。未回答追问、正在运行或只读时不提供建议；建议失败不影响已完成回复，也不补固定建议。请求共用当前任务的调度、取消和本地用量遥测入口，不访问官网演示建议接口。

Connection State 由项目读取请求和浏览器连接事件驱动。断线后保留当前画面并重试读取，恢复连接不重新提交生成命令；发送确认丢失时，按请求标识查询已有任务。手动重试相同未确认命令沿用标识，服务端保存最近 100 个受理标识，重复受理返回现有状态。不同标签页同时开始仍受工作区并发保护。

主动停止使用原版输入框的停止按钮，保存为 `stopped`，保留已完成图和原任务的目标图 ID、修改说明、文档样式。恢复接口继续校验被停止的任务 ID，并启动关联原任务的新执行段，仅处理该范围中未完成的图；首页不另设继续按钮。读取项目时，服务会核对运行是否早于当前 API 进程且已无执行控制器；确认旧进程遗留后保存为可继续的中断状态，保留对话、成果与目标范围。恢复状态不会自动调用模型。此机制适用于当前单 API 实例部署，不提供跨实例任务迁移。

输入草稿按项目保存在当前浏览器标签页的 `sessionStorage`，切换项目或刷新时自动恢复未发送文字。发送失败保留草稿，服务端确认受理后才清除。编辑请求失败后恢复原版编辑器中的修改，不清除另一个普通消息草稿。草稿不跨设备同步，浏览器禁用存储时仍可正常发送。

### Token 展示

Context Display 使用源码的数字提示和悬浮明细，遵循原版 AI SDK hook 的口径，读取最近一次实际报告用量的主会话调用总量，及其输入、缓存和输出。分母优先采用模型资料容量，资料未知时使用明确标注的实际运行预算；没有实际报告用量时不编造数字。推理用量未提供，不展示。组件保留源码处理暂时缺失用量的行为，不追加自制占位文案或累计用量面板。

主会话累计遍历完整 Pi 持久化历史，包含压缩前调用和被替换对话的实际调用，独立于当前上下文占用；不包含并行图表、测试、说明书、摘要和后续建议调用。辅助请求由供应商遥测单独记录，首页只显示源码已有的主会话用量字段。

## 操作与维护

模型目录默认保存在运行数据目录的 model-catalog 下，可用 UML_MODEL_CATALOG_DIR 指定持久目录；部署时保留此目录。当前存储由单个 API 实例管理，不能让多个独立实例同时写同一缓存文件；多实例部署应改用共享数据库存储及统一同步任务。服务按周期自动更新；离线不会删除已有成功快照。

开发供应商初始化需要显式设置 `UML_DEMO_PROVIDER_SEED=true`；普通 `npm run dev` 不会自动创建供应商。根目录开发入口读取未入库的 `.env`，直接启动 API 或演示服务时读取 `.env.local`。已有系统供应商仅需配置 `UML_DEMO_PROVIDER_NAME`；默认供应商只需填写 `UML_DEMO_PROVIDER_API_KEY`；自定义新供应商还需名称和 `UML_DEMO_PROVIDER_BASE_URL`。默认模型为 `deepseek-v4.1-flash`，可通过 `UML_DEMO_PROVIDER_MODEL` 覆盖。实际供应商必须提供该模型及原生工具调用支持。

未指定名称或地址时，使用演示默认供应商 Nonelinear。重复启动按名称或地址复用供应商配置并保留已存密钥；不会启用已停用或撤销的配置，不会覆盖不同地址。生产环境不执行初始化。新选择供应商时，前端沿用现有同步规则采用其默认模型；已经手动选择过的模型保持原选择。

Coding Agent 由用户主动连接 MCP，读取普通项目成果后生成代码。平台会话负责需求与图表，不自动部署或启动编码工具。

重新导入用户提供的源码时，在仓库根目录运行 `node apps/web/scripts/import-home-demo.cjs <source-directory>`；脚本校验原始 JSX 结构与样式，应用集中维护的中英文文案适配。之后运行 `node apps/web/scripts/build-home-demo-styles.mjs`，生成只作用于内容区及其弹层的样式。不要直接修改导入组件的 JSX 或样式类；数据兼容放在 integration 边界，翻译放在该边界的语言表。社区版使用 BYOK 与本地调用限流，不借用官网演示额度，也不包含平台计费。
