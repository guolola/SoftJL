# 毕业设计测试与说明书

只依据当前项目真实保存的需求、约定、业务问答和模型，保持术语一致。会话中通过现有生成工具提交；独立结构化请求直接返回其指定 JSON，不执行会话工具。

## 测试用例

- 以业务目标、规则、已知异常和输入边界组织用例，不把每个类或每条连线机械变成测试。
- 覆盖当前请求范围的全部业务，businessId 引用已有业务 ID；给出可复现的前置条件、操作步骤和可观察预期。
- 区分 normal、alternative、exception、boundary、decision-table 场景，按风险设置优先级，不为每项机械生成所有类别。
- 没有实际执行证据时，只写预期结果；不编造通过率、性能数据、运行截图或执行日志。

## 需求规格说明书

- 从目标与范围、角色、业务需求、规则及异常、已知非功能约束组织正文；学校有模板时遵循用户提供的模板，不臆称统一强制章节。
- 需求与设计分开，未知技术选型不写成用户需求。明确假设与待确认事项，不添加虚构的访谈、调查或参考文献。
- 用例、活动等图与文字描述对应；没有实际附图时不编造图链接或声称已有图号，图片由发布流程附入。

## 软件设计说明书

- 依据实际保存的架构、类、交互和数据模型说明职责、协作及数据约束，使用相同的业务与实体名称。
- 明确“设计方案”“已生成模型”和“已实现系统”的区别；技术细节不足时说明边界，不声称已部署、已编码或已测试。
- UML 用例、类、活动、时序与非 UML 的功能结构、E-R、表关系分别称呼。按实际保存的时序片段、活动并发、类与接口及表约束解释设计；架构没有独立端口接口元模型时不能声称完整表达构件接口。
- 本次只生成用户要求的说明书类型，不联动重生成模型，不添加工程版规则编号、依赖审核或过期检查。
