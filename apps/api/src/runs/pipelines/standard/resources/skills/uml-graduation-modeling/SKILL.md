## 共同原则

- 用用户的业务词汇命名，角色、业务和实体使用已保存方案中的稳定标识。粒度以表达业务含义为准，不按页面数量机械建模。
- 先确定系统边界、参与角色、主流程与关键异常；仅在缺失信息会改变模型含义时询问。合理默认明确写为假设，不能覆盖用户答复。
- 模型范围以本轮确认和工具守卫为准，不因本技能列出了其他图就生成它们。功能结构图、E-R 图、数据库表关系是辅助视图，不属于 UML 图种；总体架构只有实际采用 UML 构件语义时才可称构件视图。
- 图表通过工具参数或独立生成请求输出带 diagramKind、title、summary、notes 的按图种结构化模型，遵守当前 Schema；不输出 PlantUML、SVG 或虚构链接。保留已有有效 ID，先读再改，只改变本轮目标；会话正文解释实际结果。
- 规范允许但当前 Schema 没有的元素应说明表达限制，不能伪装成普通节点、杜撰字段或声称已实现。现有时序 alt/opt/loop/par、活动并发与对象流、接口实现均按对应结构表达；架构端口、独立部署或状态图等不在本次八类支持范围内。
- 复用工程建模的模型结构与记法，不引入工程审核、来源规则编号、依赖追踪或过期联动；不要填写无依据的 sourceRequirementIds 等来源字段。
- 在独立结构化生成请求中，直接使用随请求提供的本技能及对应参考，返回指定 JSON；无需执行会话工具或重复请求范围确认。
