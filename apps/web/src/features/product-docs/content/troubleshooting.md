# 生成问题排查

## 适用场景

生成按钮不可用、任务失败、图表缺失，或旧结果提示需要更新。

## 入口位置

先看当前页面提示，再打开顶部 **生成任务**。已结束的任务可在 **运行历史** 中查看。

## 前置条件

确认问题发生的阶段和目标产物，例如需求规则、某张设计图或说明书。保留页面可见的错误信息和任务编号。

## 操作步骤

### 1. 按现象找到检查点

| 现象 | 优先检查 | 处理方向 |
| --- | --- | --- |
| 按钮不可用 | 按钮附近原因 | 补齐指定前置条件或选择有效模型 |
| 任务排队 | 队列提示 | 等待当前并发任务完成，确认服务状态 |
| 某个模型失败 | 生成任务中的失败子项 | 查看错误，修正输入或重试该项 |
| 有元素、没有图片 | 图源码与渲染错误 | 修正模型或重新渲染 |
| AI 修复未完成 | 修复候选及错误提示 | 手动补充信息，重试并确认候选 |
| 分析或设计提示需更新 | 上游需求和模型状态 | 更新受影响的产物 |
| 说明书缺图 | 对应模型的 SVG 状态 | 补齐图片后重新生成文档 |
| 权限或模型调用受限 | 成员角色、供应商账户 | 按提示检查项目权限或供应商配置 |

### 2. 定位失败范围

展开任务，只检查失败阶段。若问题仅发生在一张图，优先处理这张图；其他已成功结果仍可用于核对。

![检查任务：展开对应生成项，定位状态与阶段输出，再决定重试范围](/help/images/docs-generation-tasks.png)

### 3. 再次验证结果

修正后重试，回到产物页面检查内容与来源是否正确。若持续失败，向管理员提供任务编号、阶段名称和页面错误，便于定位。

> [!TIP]
> “生成失败”表示本次任务出现错误；“需更新”表示上游依据变了。后者应先检查来源，再决定重做哪部分。

## 结果与产物

确定具体阻塞或失败点，完成对应修正，并确认目标产物可查看或下载。

## 映射关系

按 **页面提示 → 当前任务 → 历史记录 → 对应输入或上游产物** 的顺序排查。分析问题回到需求与两张前置图；设计问题回到所需需求模型；缺图问题回到对应模型。

## 常见问题

**供应商不可用？** 在 **全局设置** 测试连接并选择当前目录中的有效模型，见[模型配置](provider-configuration.md)。

**可行性方案需更新？** 检查系统环境图和业务流程图是否仍有效，按提示补齐；有未保存草稿时先保存或处理草稿。

**恢复历史后仍有提示？** 历史快照可能使用旧需求，不会自动变成最新结果。
