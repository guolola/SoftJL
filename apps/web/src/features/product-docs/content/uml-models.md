# 生成与查看需求模型

## 适用场景

把已确认的需求表达成角色、流程、业务对象和系统约束，便于讨论和检查遗漏。

## 入口位置

左侧 **需求模型** 进入生成首页；生成后展开该阶段，打开具体模型和图表。

## 前置条件

需求规则已经确认。若页面显示质量问题或前置条件缺失，先按提示回到 **系统需求** 处理。

## 操作步骤

### 1. 按问题选择模型

| 模型 | 重点检查什么 |
| --- | --- |
| 功能结构图 | 系统功能如何分解 |
| 总体业务流程 | 跨角色流程、分支与异常 |
| 用例模型 | 谁使用系统、要完成哪些任务 |
| 领域概念模型 | 业务对象、属性和关系 |
| 原型界面关系 | 页面入口与跳转关系 |
| 部署需求模型 | 设备、运行环境、外部服务和约束 |
| 需求分析模型 | 单个用例的交互与职责 |

![需求模型概览：按本次任务选择模型，再检查右上角生成操作](/help/images/docs-uml-overview.png)

### 2. 生成所选内容

在首页选择模型，点击 **生成模型**。若出现依赖或变更确认，先核对本次新增、更新和保留的内容。进度可在顶部 **生成任务** 查看。

### 3. 对照需求检查

打开图表，检查节点名称、关系方向和条件。再进入 **元素**、**关系** 或 **跟踪矩阵**，核对具体信息和需求来源。

> [!TIP]
> 初次建模可先检查用例与业务对象，再补充其他视角。图能显示只代表渲染成功，仍需判断业务含义是否正确。

![用例模型预览：核对角色和用例关系，使用工具栏缩放或下载图片](/help/images/docs-uml-model-detail.png)

## 结果与产物

每个成功生成的模型包含结构化内容、PlantUML 图源码、SVG 图片及对应追踪数据。后续设计、测试和说明书会使用这些结果。

## 映射关系

需求规则是模型的来源；结构化模型保存元素和关系；PlantUML 用于绘图；SVG 用于查看和文档配图。**跟踪矩阵** 帮助你从元素回到原始规则。

需求中的领域概念描述业务对象，技术服务和接口在设计阶段进一步细化。界面关系图描述页面结构与导航，供后续实现参考。

## 常见问题

**某类模型没出现？** 检查生成时是否选择，以及是否因前置任务失败而跳过。

**有元素却没有图片？** 查看 **生成任务** 中图源码生成或图片渲染的错误。参见[生成问题排查](troubleshooting.md)。

**图太复杂？** 先用元素列表和筛选定位目标，再回到图中查看相关关系。

**需要手动修改？** 阅读[查看与编辑模型详情](uml-model-detail.md)。
