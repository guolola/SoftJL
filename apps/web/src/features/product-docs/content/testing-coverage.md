# 测试用例与覆盖关系

## 适用场景

生成可执行的业务检查步骤，确认重要需求是否包含正常、异常与边界测试。

## 入口位置

项目左侧 **测试**。

## 前置条件

已有已确认需求规则和需求阶段的 **用例模型**。已有设计模型可以补充关联设计依据。

## 操作步骤

1. 打开 **测试**，检查前置条件提示。
2. 点击 **生成测试用例**。
3. 按场景类型筛选，例如正常、备选、异常、边界或决策表场景。
4. 阅读每条用例的前置条件、输入、操作步骤和预期结果。
5. 查看覆盖列，确认关键需求和用例都有合理关联；缺失时回到需求或模型页补齐依据，再更新测试。

> [!NOTE]
> 这里生成的是测试用例与覆盖关系。是否实际通过，需要在实现后的程序中执行并记录结果。

## 结果与产物

得到黑盒测试用例、优先级、需求与用例的覆盖关系，以及可用的设计引用。

## 映射关系

| 需求 | 应检查的行为 |
| --- | --- |
| 同一时段不能重复预约 | 重复提交被拒绝，且不创建额外记录 |
| 预约成功后通知学生 | 成功预约后产生对应通知 |
| 仅管理员可维护座位 | 普通学生无法执行维护操作 |


## 常见问题

**无法生成测试？** 先检查用例模型和已确认规则是否存在，按页面提示补齐。

**测试步骤太笼统？** 在需求或用例事件流中补充输入、失败条件和预期行为。

**有设计模型仍缺覆盖？** 检查需求到模型的来源关系是否明确，不能仅凭设计图存在判断已覆盖。

**覆盖数高就表示质量好吗？** 还需要核对步骤和预期结果是否有意义，以及是否实际执行。
