# 生成与检查设计模型

## 适用场景

将需求分析细化为架构、对象交互、页面和数据库设计，为实现与说明书提供依据。

## 入口位置

项目左侧 **设计模型**。生成后展开该阶段查看具体模型。

## 前置条件

已准备所选设计类型需要的需求模型，并确认相关追踪关系。不同设计的依赖不同；以首页提示为准。用例实现设计需要用例及其事件流。

## 操作步骤

### 1. 按实现问题选择设计

| 模型 | 用途 |
| --- | --- |
| 总体架构图 | 组织子系统、包与核心组件 |
| 用例实现设计 | 将用例事件流细化为对象调用 |
| 设计类图 | 定义服务、实体、接口及关系 |
| 页面导航图 | 说明页面、模块和路由导航 |
| 数据库设计 | 定义表与主外键、唯一等约束 |
| 组件关系 | 说明组件接口与依赖 |
| 部署设计 | 说明节点、运行环境与制品部署 |

![设计模型概览：选择架构、类、页面、数据库等目标产物](/help/images/docs-design-overview.png)

### 2. 生成并检查依赖

选择设计模型，发起生成。若提示补齐需求模型或前置设计，先核对所需内容；在 **生成任务** 查看各子任务进度。

### 3. 核对设计细节

打开生成结果，检查元素和关系。例如预约功能是否体现身份检查、可用性判断和重复预约限制。再进入 **跟踪矩阵** 检查需求来源。

> [!TIP]
> 设计图过于复杂时，先从一个关键用例检查事件流与调用顺序，再逐步核对类、表和接口。

## 结果与产物

获得设计模型、图源码、SVG 图片与需求到设计的映射。已保存的结果可用于[软件设计说明书](documents-delivery.md)。

## 映射关系

用例与事件流支持用例实现设计；领域概念支持设计类和数据库；部署需求支持部署设计。每个设计元素还应能解释它来自哪些需求或前置设计，详见[检查需求到设计的覆盖](design-traceability.md)。

## 常见问题

**无法开始生成？** 按页面提示补齐或更新依赖，尤其检查需求模型的来源是否过期。

**某个用例没有实现设计？** 确认需求用例中确实存在该用例，并包含可用事件流。

**页面导航与业务流程有什么区别？** 页面导航描述界面之间的跳转；业务流程描述业务动作、职责和条件。

**生成失败？** 在 **生成任务** 找到失败子任务，再检查错误或重试。
