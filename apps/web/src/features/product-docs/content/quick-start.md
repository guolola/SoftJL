# 快速开始

## 适用场景

第一次做毕业设计、课程设计或 UML 作业，可以先完成一个范围清楚的小项目：**创建项目 → 整理需求 → 生成模型 → 按目标完善设计、测试与文档**。本页使用“图书馆预约系统”示例，帮助你找到项目起点。

> [!TIP]
> 先用一段范围清楚的需求走通流程。每一步检查结果后再继续，比一次生成所有内容更容易发现问题。

## 入口位置

打开[项目首页](/projects)，点击 **新建项目**。已有项目时，点击对应项目卡片进入工作台。

## 前置条件

- 已登录，并拥有可编辑的项目。
- 已在 **账号设置 → 全局设置** 选择可用供应商和默认模型；未配置时，先阅读[配置模型供应商](provider-configuration.md)。

## 操作步骤

### 1. 创建项目

在 **新建项目** 中填写名称“图书馆预约系统”，按页面步骤选择可见范围与项目归属，确认后进入项目。详细说明见[创建与进入项目](project-basics.md)。

### 2. 输入需求并检查规则

在左侧 **系统需求** 中输入以下内容，再点击 **提取需求规则**（修改已有需求时显示 **更新需求规则**）：

```text
图书馆预约系统允许学生登录后查询空闲座位，选择日期和时间段提交预约。
同一学生同一时间段不能重复预约。预约成功后，系统向学生发送通知。
管理员可以维护座位、查看预约记录，并处理异常取消。
```

检查是否包含学生、管理员、预约约束和异常处理。出现自动补齐或修复候选时，逐条决定是否采纳。详细说明见[整理需求与确认规则](requirements.md)。

![系统需求页：在输入区说明业务，再检查下方提取的规则](/help/images/docs-requirements-current.png)

### 3. 生成并检查需求模型

打开 **需求模型**，先选择 **用例模型** 与 **领域概念模型**，点击 **生成模型**。生成过程中可在顶部 **生成任务** 查看进度。

完成后展开左侧 **需求模型**，打开对应图表。确认角色、业务对象和关系符合需求；再打开 **跟踪矩阵**，查看元素对应的需求规则。

### 4. 按目标继续

| 你现在要完成什么 | 下一步 |
| --- | --- |
| 评估成本、风险和实现路线 | [完成可行性分析](feasibility-analysis.md) |
| 细化架构、类、页面与数据库 | [生成设计模型](design-models.md) |
| 检查正常、异常与边界场景 | [生成测试用例](testing-coverage.md) |

课程作业只要求部分模型时，先完成对应模型并检查。毕业设计需要系统实现时，继续补齐设计和验收条件，再导出设计资料，在自己的代码仓库中编码和验证。

### 5. 生成并下载说明书

打开 **说明书**，选择文档类型，按页面提示补齐所需产物后生成。检查图表和正文，再下载 DOCX。完整操作见[说明书生成与下载](documents-delivery.md)。

## 结果与产物

你会得到一个保存需求、模型和说明书的项目。判断是否完成时，检查：**规则已确认、图表可查看、来源可追踪、说明书可下载**。

准备阶段汇报或答辩时，可以沿着需求、设计与测试的关联梳理讲解依据。提交前按课程或学校要求调整文档，核对配图、正文和系统实际运行结果。

## 映射关系

需求文本说明业务目标；需求规则把目标拆成可核对的条目；模型表达角色、流程和结构；说明书汇总这些结果。修改需求后，下游内容可能显示 **需更新**，按提示更新即可。

## 常见问题

**只有题目，没有完整需求？** 先写清“谁使用系统、要完成哪些操作、有哪些限制和异常情况”，再检查平台抽取的规则。业务范围不确定时，先与指导老师确认。

**导出的说明书就是毕业论文吗？** 平台生成可行性研究报告、需求规格说明书和软件设计说明书等工程文档。它们可作为项目报告的材料；论文结构、研究论证与学校格式要求仍需自行完善。

**生成按钮不可用？** 先阅读按钮附近的原因，再补齐对应条件。常见原因是未选择模型、需求修复待确认或前置模型缺失。

**某一步失败？** 在 **生成任务** 查看失败项，只重试受影响的部分。参见[生成问题排查](troubleshooting.md)。

**视频中的界面与当前页面不同？** 视频可用于了解整体流程，实际入口和操作名称以本页文字步骤为准。
