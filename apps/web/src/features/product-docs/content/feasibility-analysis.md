# 完成可行性分析

## 适用场景

在投入实现前，明确系统边界、业务流程、成本和风险，并形成可行性研究报告。

## 入口位置

项目左侧 **可行性分析**。阶段首页显示各项产物的生成入口与状态。

## 前置条件

- 已输入需求，并[生成与确认需求规则](requirements.md)。
- 已选择可用的供应商与模型，并确认供应商账户可用。
- 准备已知的预算、周期、人员和其他约束，作为补充资料。

## 操作步骤

先在 **目标产物** 中勾选本次要生成的卡片。下图尚未勾选，因此生成按钮不可用。

![可行性分析入口：勾选需要的目标产物后，再开始生成](/help/images/docs-feasibility.png)

### 1. 检查系统边界

生成 **系统环境图**，核对系统、外部参与者、外部系统与它们之间的关系。重点看是否漏掉业务角色或实际依赖的服务。

### 2. 检查业务流程

生成 **业务与系统流程图**，检查人员操作、系统处理、判断条件和异常分支。它可以直接基于已确认需求独立生成。

图保存完整后，展开侧栏对应图，打开 **元素**、**关系** 或 **跟踪矩阵** 查看来源；也可导出 SVG 图片或 PlantUML 图源码。

### 3. 比较并保存实现方案

选择 **实现方案**。页面会自动勾选缺失或需更新的前置图，按 **系统环境图 → 业务与系统流程图 → 实现方案** 的顺序生成；已有效的图会复用。

阅读候选方案的职责划分、成本收益、风险和可行性结论。补充实际资料，检查采用方案并保存修改。

### 4. 生成研究报告

进入 **说明书**，选择 **可行性研究报告**。先处理依赖提示，再生成并检查报告，参见[说明书生成与下载](documents-delivery.md)。

> [!NOTE]
> 修改需求、流程或方案后，相关下游产物可能显示 **需更新**。按提示更新受影响的部分；仅重新渲染图片不会让方案自动过期。

## 结果与产物

| 产物 | 用于回答 |
| --- | --- |
| 系统环境图 | 系统与哪些人、外部系统交互？ |
| 业务与系统流程图 | 谁在什么条件下完成哪些步骤？ |
| 候选实现方案 | 如何实现、需要多少投入、有何风险？ |
| 可行性研究报告 | 为什么选择这一方案，结论与依据是什么？ |

## 映射关系

两张图的业务内容应来自已确认规则。实现方案综合需求、两张图与补充资料；报告汇总当前有效的分析结果。流程图可独立查看和导出，生成报告前也会检查它是否有效。

## 常见问题

**生成按钮不可用？** 先看旁边的原因：可能是规则待确认、未选择有效模型、次数不足或已有任务运行。

**侧栏没有业务与系统流程图？** 只有模型、图源码和图片全部保存成功后，首次生成的图才会出现在侧栏。阶段首页始终保留生成入口。

**旧方案提示补齐依赖？** 点击 **补齐依赖**，在概览中生成所需产物。仅保存文字修改，不能让未使用最新流程的方案变成最新版本。

**图没有串起所有功能？** 流程图优先展示有需求依据的业务闭环。先核对规则是否明确说明流程关系，再补充遗漏的步骤。
