# 处理需求待确认项

## 适用场景

页面提示 **需求已修改**、**请先确认需求规则修复结果** 或质量问题，导致后续生成无法开始。

## 入口位置

**系统需求** 中的规则列表、质量提示区域，以及生成按钮旁的原因说明。

## 前置条件

已输入需求并生成过规则。先确定当前想继续的阶段，例如可行性分析或需求模型。

## 操作步骤

1. **核对文本版本。** 如果修改过原文，检查现有规则是否仍然完整、准确。
2. **检查待确认项。** 逐条比较补齐或修复建议与原需求。
3. **作出明确选择。** 对修复候选选择 **采纳** 或 **拒绝**；只需确认的质量提示可点击 **确认提示**。
4. **重新检查生成入口。** 提示消失后继续；仍有阻塞时按最新提示处理。
5. **大幅修改后重新生成。** 新增角色、流程或关键约束时，重新生成规则并复核下游模型。

> [!TIP]
> “确认”表示你接受这条内容作为后续分析的依据。先检查含义，再继续生成。

## 结果与产物

| 页面状态 | 你需要做什么 |
| --- | --- |
| 待确认 | 审阅候选内容并决定是否采纳 |
| 需求已修改 | 核对规则与最新文本，必要时重新生成 |
| 前置条件缺失 | 按按钮旁的说明补齐指定内容 |
| 可生成 | 开始目标阶段并检查结果 |

## 映射关系

已确认需求版本会被可行性分析、需求模型和其他结果引用。原文或规则更新后，下游可能显示 **需更新**；这表示旧结果仍可查看，但需要重新核对。

## 常见问题

**为什么 AI 修复完还不能继续？** 修复候选仍需要人工确认，避免错误理解进入后续模型。

**不接受修复会怎样？** 对修复候选选择 **拒绝** 后也会标记为已确认。先判断业务含义，遗漏的约束仍可能影响模型或测试。

**为什么模型显示需更新？** 它使用的需求版本与当前版本不同。完成规则审阅后，更新受影响的模型。
