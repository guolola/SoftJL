# 模型选择指南

## 适用场景

供应商提供了多个模型，需要选择一个能稳定完成当前需求、建模或文档任务的模型。

## 入口位置

在 **账号设置 → 全局设置** 查看供应商与默认模型；生成前在项目页面核对当前选择。

## 前置条件

已经[连接供应商](provider-configuration.md)，并获得可用模型列表。准备一份范围较小、结果容易检查的需求作为样例。

![模型选择入口：在全局设置中选择当前供应商与默认模型](/help/images/docs-account-global-settings.png)

## 操作步骤

1. **先确认可用。** 从当前供应商的目录中选择模型并通过连接测试。
2. **试一次需求整理。** 用固定样例生成规则，检查是否漏掉角色、约束和异常。
3. **试一次建模。** 检查图能否生成、业务含义是否正确，以及元素是否有需求来源。
4. **比较实际结果。** 对相同输入记录成功情况、耗时和费用，再选择默认模型。
5. **长任务单独验证。** 设计模型和长说明书可能有不同要求，不能只凭一次短任务判断。

> [!TIP]
> 优先选择能稳定给出完整、可检查结果的模型。速度和单次价格应结合失败重试的成本一起比较。

## 结果与产物

得到适合当前任务的模型选择，以及可以重复验证的样例。以后更换供应商或模型时，可用同一份样例再次比较。

## 映射关系

供应商决定可选择的模型集合，模型调用费用由对应供应商账户结算。社区版不提供平台计费或生成额度。

## 常见问题

**为什么不提供固定排行榜？** 模型版本、供应商路由与可用性会变化。以当前账号能用的模型和实际结果为准。

**连接测试成功就一定能完成项目吗？** 连接测试验证基础可用性，完整任务仍需要足够上下文和稳定输出。

**如何减少试用成本？** 先用小样例比较，再让少量候选完成整个流程。

**模型突然不可用？** 刷新供应商目录并选择有效模型，检查原模型是否已下线或被限制。
