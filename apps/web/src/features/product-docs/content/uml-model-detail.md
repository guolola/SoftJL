# 查看与编辑模型详情

## 适用场景

检查图中的某个角色、实体或关系，查看它的来源，或修正生成结果。

## 入口位置

展开左侧 **需求模型** 或 **设计模型**，打开具体模型的 **元素**、**关系** 或 **跟踪矩阵**；也可从图表中的元素进入详情。

## 前置条件

对应模型已生成。有结构化模型但图片生成失败时，仍可先检查元素内容与图源码。

![模型预览：左侧展开模型内容，右上角进入编辑与图片操作](/help/images/docs-uml-model-detail.png)

## 操作步骤

### 1. 定位要检查的元素

打开目标模型，用搜索或类型筛选缩小范围。点击元素查看名称、属性和关联关系，例如用例模型中的“提交预约”。

### 2. 检查关系与来源

查看关系的起点、终点和方向，再打开 **跟踪矩阵**，核对元素引用的需求。不能仅凭图上位置判断业务含义。

### 3. 修改并保存重绘

在表单中修改相关字段。不同模型提供不同字段，例如用例边界、活动分支、顺序消息或数据库约束。根据字段诊断修正草稿，再保存并重绘。

> [!NOTE]
> 删除元素后，如果关系仍引用它，页面会保留草稿并指出问题。先修正引用，才能保存有效结果。

![用例编辑：核对名称、目标与前后条件，完成字段检查后保存并重绘](/help/images/docs-model-element-edit.png)

### 4. 核对受影响的下游

检查修改后的图与追踪关系。若设计或说明书提示 **需更新**，按提示重新生成相关内容。

## 结果与产物

得到可检查的元素、关系、图源码和图片。手动修改后的内容应保持业务含义、关系端点与图表一致。

## 映射关系

例如需求中的“学生提交预约”对应学生角色和预约用例；领域中的预约对象可进一步对应设计类与数据库表。追踪主要面向业务元素，辅助绘图结构不一定单独对应需求。

数据库主外键标记与表间连线由表约束生成，需要通过约束字段维护。

## 常见问题

**元素存在但图为空？** 检查图源码或图片渲染错误，修正后重新渲染。

**跟踪矩阵缺项？** 先检查需求是否明确，再检查模型是否实际覆盖；不要把缺失来源直接视为有效映射。

**保存时提示端点不合法？** 关系类型限制了可选起点和终点，按字段提示重新选择。

**模型改了但说明书没变？** 说明书保留生成时的内容，需要重新生成对应文档。
